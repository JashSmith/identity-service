# پیامک

درگاه یک لایه مشترک برای ارسال پیامک دارد. ورود با کد پیامکی روی همین لایه ساخته شده است ([ورود با پیامک](sms-login.md)). هر سازمان سرویس پیامک و حساب خودش را در کنسول انتخاب و تنظیم می‌کند، و قابلیت‌هایی که پیامک لازم دارند (کد ورود، بازیابی رمز، اعلان‌ها) فقط با همین لایه کار می‌کنند، نه مستقیم با یک سرویس خاص. افزودن سرویس تازه یعنی نوشتن یک کلاس، بدون تغییر در بقیه سامانه.

## تنظیم در کنسول

«تنظیمات احراز هویت ← پیامک» (نشانی مستقیم: `/settings?tab=sms`):

1. سرویس را انتخاب کنید. فرم تنظیمات از روی فیلدهای همان سرویس ساخته می‌شود.
2. فیلدها را پر کنید. کلیدهای محرمانه پس از ذخیره هیچ‌وقت نمایش داده نمی‌شوند؛ اگر خالی بگذارید، کلید قبلی می‌ماند.
3. «ارسال پیامک فعال است» را روشن کنید و ذخیره کنید. فعال کردن بدون فیلدهای الزامی پذیرفته نمی‌شود.
4. با «ارسال پیامک آزمایشی» یک پیام کوتاه به شماره خودتان بفرستید (هر ۲۰ ثانیه یک بار برای هر سازمان).

تنظیمات هر سرویس جدا نگه داشته می‌شود؛ اگر از کاوه‌نگار به سرویس دیگری بروید و برگردید، کلید کاوه‌نگار سر جایش است.

## سرویس‌های موجود

| شناسه | سرویس | ارسال واقعی |
|---|---|---|
| ‏`kavenegar` | کاوه‌نگار | دارد |
| ‏`development` | حالت آزمایشی | ندارد؛ پیام‌ها در کنسول نمایش داده می‌شوند |

### کاوه‌نگار

| فیلد | توضیح |
|---|---|
| کلید API | از پنل کاوه‌نگار، «تنظیمات حساب ← کلید API» |
| شماره فرستنده | اختیاری؛ خالی یعنی شماره پیش‌فرض حساب |
| نشانی سرویس | اختیاری؛ فقط اگر از نشانی دیگری (مثلاً پروکسی داخلی) استفاده می‌کنید |

ارسال با `POST https://api.kavenegar.com/v1/{API-KEY}/sms/send.json` انجام می‌شود. چون کلید بخشی از نشانی است، این درخواست‌ها نه در لاگ ثبت می‌شوند و نه در ردیابی OpenTelemetry، و پیام‌های خطا هرگز نشانی را ندارند. کدهای خطای مستند کاوه‌نگار به توضیح تبدیل می‌شوند، مثلاً `403` (کلید نامعتبر)، `411` (گیرنده نامعتبر)، `412` (خط فرستنده نامعتبر) و `418` (اعتبار ناکافی).

### حالت آزمایشی

هیچ پیامی ارسال نمی‌شود و آخرین پیام‌ها در همان صفحه کنسول (فقط برای سازمان خود مدیر) نمایش داده می‌شوند. این حالت برای توسعه، آزمایش و نمایش است و در محیط عملیاتی نباید فعال بماند.

## افزودن سرویس پیامک تازه

یک کلاس که `ISmsProvider` را پیاده می‌کند، در پروژه `src/Infrastructure/Identity.Infrastructure.Sms`:

```csharp
public sealed class MySmsProvider(IHttpClientFactory httpFactory) : ISmsProvider
{
    public string Id => "my-sms";                       // حروف کوچک لاتین؛ در تنظیمات ذخیره می‌شود
    public string DisplayName => "سرویس پیامک من";
    public string Description => "ارسال از طریق ...";
    public bool SendsMessages => true;

    // کنسول فرم تنظیمات را از همین فهرست می‌سازد. Kind: text، secret، phone یا url
    public IReadOnlyList<SmsFieldDto> Fields { get; } =
    [
        new("token", "توکن دسترسی", "secret", Required: true),
        new("sender", "شماره فرستنده", "phone", Required: false, Placeholder: "3000xxxx"),
    ];

    public async Task<SmsSendResult> SendAsync(SmsMessage message, IReadOnlyDictionary<string, string> settings, CancellationToken ct)
    {
        // message.To همیشه به شکل +989xxxxxxxxx است
        var response = await httpFactory.CreateClient("sms-my").PostAsJsonAsync("https://...", new { to = message.To, text = message.Text }, ct);
        return response.IsSuccessStatusCode ? new SmsSendResult(true) : SmsSendResult.Failed($"{(int)response.StatusCode}");
    }
}
```

و ثبت آن در `Program.cs` درگاه:

```csharp
builder.Services.AddSmsProvider<MySmsProvider>();
```

همین کافی است: سرویس در کنسول ظاهر می‌شود، فرم تنظیماتش ساخته می‌شود و کلیدهای `secret` پنهان می‌مانند. چند قاعده:

- کلید یا توکن را هرگز در لاگ یا متن خطا نیاورید. اگر کلید در نشانی است، کلاینت HTTP را با `RemoveAllLoggers()` ثبت کنید و روی درخواست `request.Options.Set(SmsHttp.SuppressTelemetry, true)` بگذارید.
- شماره‌ها را برای لاگ با `PhoneNumbers.Mask` بپوشانید.
- خطاهای سرویس را با `SmsSendResult.Failed("...")` و یک توضیح کوتاه برگردانید؛ استثنا پرتاب نکنید.

## ارسال پیامک از کد درگاه

```csharp
var result = await smsService.SendAsync("09121234567", "کد ورود شما: 482913", ct);
```

‏`SmsService` شماره را با هر نگارشی می‌پذیرد (`09..`، ‏`+98..`، ‏`0098..` یا ارقام فارسی و عربی) و این خطاها را برمی‌گرداند: `sms.disabled` (پیامک برای سازمان فعال نیست)، `sms.invalid_number` و `sms.send_failed` (سرویس پیام را نپذیرفت).

## محل ذخیره و امنیت

تنظیمات مثل بقیه داده‌ها فقط در Keycloak و به‌صورت ویژگی‌های Realm سازمان ذخیره می‌شوند:

| ویژگی Realm | مقدار |
|---|---|
| ‏`iam.sms.enabled` | ‏`true` یا `false` |
| ‏`iam.sms.provider` | شناسه سرویس فعال |
| ‏`iam.sms.<provider>.<field>` | مقدار هر فیلد، مثلاً `iam.sms.kavenegar.apiKey` |

‏Keycloak 26.4 با به‌روزرسانی Realm کل فهرست ویژگی‌ها را جایگزین می‌کند؛ بنابراین درگاه همیشه فهرست کامل را می‌خواند، فقط ویژگی‌های `iam.sms.*` را عوض می‌کند و همه را برمی‌گرداند تا ویژگی‌های دیگر Realm از دست نروند. مثل کلیدهای سرویس‌های ورود بیرونی، مدیران خود Keycloak این مقادیر را می‌بینند؛ دسترسی کنسول Keycloak را محدود نگه دارید.

## ‏API

| مسیر | دسترسی | توضیح |
|---|---|---|
| ‏`GET /settings/sms/providers` | ‏Settings Read | سرویس‌های نصب‌شده و فیلدهایشان |
| ‏`GET /settings/sms` | ‏Settings Read | تنظیمات با کلیدهای پنهان (`**********`) |
| ‏`PUT /settings/sms` | ‏Settings Manage | ذخیره؛ فرستادن `**********` کلید قبلی را نگه می‌دارد |
| ‏`POST /settings/sms/test` | ‏Settings Manage | پیام آزمایشی به `{ "phoneNumber": "0912..." }`؛ هر ۲۰ ثانیه یک بار (`sms.test_rate_limited`) |
| ‏`GET /settings/sms/outbox` | ‏Settings Manage | آخرین پیام‌های حالت آزمایشی همین سازمان |
